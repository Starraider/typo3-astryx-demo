Native components use the global `astryx` namespace. Helper ViewHelpers use `ax`; StyleX uses the connector's global namespace.

Unknown component arguments raise Fluid errors. Invalid recipe values fall back to the first value in each dimension; Heading falls back to h2. Invalid button types become button. Unknown icons become the information symbol.
The allowlisted icons are menu, close, arrow-left, arrow-right, download, info, check, warning, error and sun. Information and Error use circled symbols. No stored SVG or arbitrary markup is accepted.
Notice's backend `icon` field offers `check`, `warning`, `error` and `info` (Information), with an empty default/None option and block-owned SVG previews matching the native Icon shapes. A selected icon renders through the native Icon component as a decorative 24px inline SVG beside the translated status label in the frontend and backend preview. Status controls the colors independently. Empty selections retain the status dot. Existing field identity and stored strings are retained; TYPO3 shows unmatched legacy values rather than rewriting them. Legacy names supported by the native component still render; unknown values use the Information symbol. No JavaScript or automatic alert announcement is required.
Links go through TYPO3 typolink. Disabled links have no href. Disabled/loading buttons emit the disabled attribute; enabled buttons omit it. Icon-only controls keep their label as accessible text.
Text's richText and Card's body explicitly use TYPO3 parseFunc_RTE. Plain text and component slots keep Fluid escaping. Named slots accept composed component markup.
Partials in `Partials/Astryx` are scalar bridges to the same component implementation. Use native components for named slots.
Heading resolves its default slot once and emits h1–h6 (or the h2 fallback) only when text or rendered slot content remains nonempty after trimming whitespace. The string `0` is meaningful content. Text and slot are additive: an explicitly empty slot contributes nothing and does not override nonempty text. Text stays escaped; composed slot markup and its existing escaping are preserved. Trimming only tests presence and does not alter rendered content. The subtitle remains an independent paragraph, including for subtitle-only native calls. The scalar Heading partial uses the same guard; the CMS Header still suppresses Hidden or absent titles.
Card renders its escaped title at the selected heading level when no heading slot is supplied. A supplied heading slot replaces that fallback, including an empty slot used to hide the heading. Shared Card styling separates media from the following badge or heading by the 16px space-4 token, including standalone Cards and Card Grid items. Card Grid uses each item's title with the default h3 level.
Card renders primary and secondary CTAs in a wrapping action group. Each CTA requires its link and label; the secondary CTA also works without a primary CTA and uses the secondary Button variant. Both retain TYPO3 link handling and escaped labels.

## Records and layouts

Content wrappers retain one canonical `c<uid>` anchor per rendered record, while repeated occurrences and component internals use request-scoped namespaces. Root navigation instances and complete recursive branch paths remain unique. TreeList’s `id` is a readable namespace prefix, not a literal DOM ID. Authored HTML and plugin IDs remain owned by their producers and can be inspected with the opt-in diagnostic. See [Occurrence identifiers](OccurrenceIdentifiers.md) for the allocation, reference and adapter contract.

The Astryx Site Set's `PageTsConfig/content_types.tsconfig` removes the 17 standard CTypes without Astryx renderers from the CType selector and new-content wizard through `TCEFORM.tt_content.CType.removeItems`. The list is additive; supported retained CTypes and installed plugins stay available. Page-scoped `TCAdefaults.tt_content.CType` selects `astryx_text` for new records. This changes editor choices without deleting type definitions or converting existing records.

Content Block names are `astryx/<name>` with explicit `astryx_<name>` CTypes. The catalogue is heading, text, textmedia, image-only, card, list, table, divider, downloads, hero, card-grid, notice, accordion, carousel, container-single-col, container-two-col, container-two-col-25-75, container-two-col-75-25, container-three-col, container-four-col, code-block and classic-gallery.
Backend content icons use a shared 64×64 viewBox, 3-unit rounded outlines, transparent backgrounds and the primary palette `#ed6d05` (rgb(237, 109, 5)), `#c49aef` (rgb(196, 154, 239)) and `#96b3f8` (rgb(150, 179, 248)), with `#25324b` for outlines. Each Content Block owns `assets/icon.svg`; Content Blocks registers and publishes it. The retained Sitemap, Subpages, Selected Pages, Shortcut and HTML icons live in `Resources/Public/Icons/` and are registered in `Configuration/Icons.php`; their CType items and record type icons use the same identifiers. Icons have no scripts, external resources or font dependencies.

Core header/bodytext/image/assets/media fields are reused where appropriate. Collection tables have stable `tx_astryx_*` identities; Content Blocks owns localization, workspace and relation metadata. Do not manipulate relation counters directly outside fixture construction.

Backend heading controls use Content Blocks palettes to place `header_layout`, `header_position` and the existing block-specific `heading_size` field in that order on one row. The palette keeps the original field identities, translations, choices and defaults, including Classic Gallery's Small default. Blocks and retained core types without a heading-size field group only the two core selectors. TYPO3's native form grid controls responsive wrapping.

## Theme and cascade

Stone adapts the [official v0.6.7 preview](https://astryx.atmeta.com/themes?theme=stone) and CLI template. It uses Montserrat headings, Figtree body/labels and JetBrains Mono code, bundled locally for frontend, RTE and previews. Semantic h1–h6 sizes are 27/22/18/14/11/9px, with 36/32/28/20/16/16px leading; h3/h4 are weight 700 and the other semantic headings are 600. Body and labels are 14px/20px, supporting text 12px/17.454px. Display uses 43px/52px, weight 400. Heading `medium` follows the semantic level, `small` maps to h3, `large` to h1 and `display` to display2. Other themes retain their existing type scale.

Stone includes the complete upstream semantic, ten categorical hue and syntax color sets for light/dark modes. Primary text/accent is `#25252a`/`#f3f3f5`, secondary text `#5e5e63`/`#ababb0`, body `#f3f3f5`/`#111015`, surface `#ffffff`/`#1b1b1f`, card `#ffffff`/`#242325` and popover `#ffffff`/`#25252a`. Buttons have pill radii and 14px labels; secondary buttons use transparent fill and a 1.5px emphasized border; destructive buttons use the categorical red fill/text. Small/medium/large heights are 28/32/36px. Badges have categorical fills/text and no borders; `accent` maps to upstream `info` blue. Notice adapts Banner with categorical fills and matching heading/body colors. Card normal padding is 12px and its outlined border uses the standard border token. TYPO3 layouts, content and supported component contracts remain native adaptations rather than copies of the reference site's page layout.


Site settings `Astryx.theme` and `Astryx.mode` default to neutral/system. Rootline overrides `tx_astryx_theme` and `tx_astryx_mode` inherit independently, with the nearest valid page value winning. Invalid stored values are ignored.
`Astryx.allowUserMode`, enabled by default, shows the header icon toggle and enables a saved browser preference which wins over page/site mode. Storage failure still permits in-page switching. The color mode is saved; the Neutral, Stone or Ocean palette remains a site/page setting.
Public tokens use explicit `--astryx-*` names. Source token declarations and theme declarations generate the attribute bridge and editor CSS. Each nested theme boundary repeats the complete token set so it does not inherit a sibling or parent theme's palette.
Layer order is reset, astryx-base, StyleX priority1 through priority5, astryx-theme, product. The compiler's actual priority layers are preserved. Product overrides belong in the final layer. Unlayered third-party styles follow the CSS cascade normally.
Neutral/Stone adapt verified upstream 0.6.5 values. Ocean is local. See `Build/adaptations.json`, `Build/upstream-versions.json` and `THIRD_PARTY_NOTICES.md`. `Documentation/Examples/Brand.css` demonstrates a custom brand boundary.

## Browser and accessibility scope

Target browsers support light-dark(), native dialog, ResizeObserver and CSS scroll snap: Chromium 123+, Firefox 120+ and Safari 17.5+. Container queries have a viewport fallback. These are support targets; tested versions are recorded separately in Validation.md.
WCAG 2.2 AA verification includes keyboard, focus return, names, landmarks, semantic headings, readable status labels, contrast and responsive reflow. Editors remain responsible for image alternatives, video captions and heading hierarchy.
The Accordion uses separate compact bordered cards in Single mode, matching the [Collapsible Group overview](https://astryx.atmeta.com/components/CollapsibleGroup): 8px gaps, 11px padding and token-based rounded corners on each item. Multiple mode retains one compact bordered card with 16px gaps. Both use 14px semibold triggers, secondary body text, and an end chevron that turns upward when expanded. Native details provides Enter/Space disclosure behavior before JavaScript. Single mode uses native named disclosures without JavaScript and normalizes multiple defaults to the first open item with JavaScript; zero open items is allowed. The controller animates expansion and collapse using the theme duration and easing, includes each item's padding and border in its animation height, synchronizes aria-expanded, and makes closing content inert. Reduced motion skips both height and chevron animations. Multiple mode preserves independently opened sections. Carousel has no autoplay. Optional controls use 8px clickable dots between previous/next arrows, with the active page marked by `aria-current="page"` and the theme text color. Dot targets are 24×44px. Pagination position is one of top-left, top-center, top-right, bottom-left, bottom-center (default/fallback), or bottom-right; the entire control group is rendered before/after the track in matching keyboard order. Alignment is physical left/right, including RTL. Dots represent unique reachable scroll-snap positions, recalculated on resize; all-fit tracks hide controls. Scrolling and dot/arrow activation synchronize the active dot and a translated, visually hidden page announcement. Controls preserve focus, reduced motion uses immediate scrolling, and the track stays readable and scrollable without JavaScript. This is a native scroll-snap adaptation of the upstream Pagination dots example. Mobile navigation uses native modal focus handling and closes on Escape or a desktop breakpoint change.

## Initial media scope

Captions stay below the photo on the backdrop, without another panel. Thumbnail focus uses adjacent 3px white/black inset rings. Nonempty captions join the modal Tab order for keyboard scrolling; Escape restores opener focus. Forced colors uses system caption/counter and thumbnail-focus colors, with a fixed black/white pair for external SVG controls. Disabled controls remain exempt from enabled contrast thresholds. Hero supports one image, split/centered/protected-overlay layout, neutral/accent treatment and logical text alignment. Its text and caption panels use 54% transparency (46% white opacity) with black foregrounds in every theme and mode; themed primary controls retain their own contrast-safe colors. Hero video and decorative/autoplay video are outside the initial contract. Textmedia supports TYPO3's standard image/video/audio renderers with controls; an optional FAL image supplies a video poster. The shared image partial retains TYPO3's default FAL crop variant, captions and alternative text, emits 480/960/1200 srcsets and dimensions, and offers original/wide/landscape/square display ratios. No lightbox is advertised or loaded.

## Header navigation

The header contains the configured logo and the TYPO3 page-tree menu with up to three levels. Parent pages remain links. The adjacent disclosure opens their submenu with a mouse click, touch, Enter or Space. Escape closes the submenu and restores focus. Outside clicks and moving focus outside the submenu close it. On small screens the menu opens in a modal dialog. Native disclosures and page links remain usable without JavaScript.

Desktop dropdowns visually adapt [Astryx DropdownMenu v0.6.8](https://astryx.atmeta.com/components/DropdownMenu): 4px surface padding, 32px rows with 6px/8px padding, 2px row spacing and rounded highlights. Each panel takes the width of its own longest label, capped by the available viewport; opening a descendant does not widen the parent. Third-level panels fly out beside their parent row, switch to the opposite side when necessary and remain reachable across the pointer gap. Hover or Right Arrow opens a branch; Left Arrow or Escape closes it and returns focus to its disclosure. Directional arrows mirror in RTL; Up/Down/Home/End move among the current panel's links. Enter still follows page links, and Tab retains the normal link/disclosure order. Mobile navigation keeps in-flow disclosures and 44px targets. These are native navigation links, without action-menu roles or the upstream React runtime.

The following typed settings are available in the TYPO3 site settings editor. Override them per site in `config/sites/<site>/settings.yaml` using flat keys:

```yaml
Astryx.pinnedHeader: true
Astryx.allowUserMode: true
Astryx.showLanguageMenu: true
```

`Astryx.pinnedHeader` keeps the bar visible while scrolling. Set `Astryx.allowUserMode` to `false` to hide the theme switcher and ignore stored visitor preferences. The configured site or page color mode then applies. Set `Astryx.showLanguageMenu` to `false` to disable the language menu and its data processor. All three settings default to `true`.

The language selector only appears when the site has more than one enabled language. Languages and translated URLs come from TYPO3 site handling. Missing translations appear as disabled text. Add languages to the site's `config.yaml` and translate pages in the backend to make those links available.

The header shows the uppercase two-letter language code; the dropdown keeps each full `navigationTitle`. The header trigger shares the main menu links' typography, padding, colors and hover background without a border. Both include a decorative 20px circular flag, matching the moon and sun icons, including disabled languages. English uses the British (`gb`) flag. The extension supplies sharp vector SVG flags for Britain and Germany; other languages use their configured site `flag` from TYPO3's core assets. A language without a configured flag retains its text label.

The language dropdown shares the main menu's `Dropdown` StyleX panel/row/link recipe: 4px panel padding, 2px row spacing, 32px desktop rows with 6px/8px padding, and 44px mobile targets. Its width follows the longest language title plus its flag and 8px gap, within the viewport. The active language keeps a selected background; unavailable translations retain disabled text and the same flag/spacing.

The theme control follows the Astryx documentation header: one borderless 44px button with a 20px moon or sun icon. It toggles between light and dark, naming the next action in its translated accessible label and tooltip. System mode follows the operating system until a visitor chooses an explicit mode; changes in system preference also update the icon. Saved preferences and `Astryx.allowUserMode: false` retain their behavior. The control stays hidden when JavaScript is unavailable.

Code Block uses a dedicated plain textarea without RTE or trimming. Its language, optional filename and line-number flag belong to `astryx/code-block` (`astryx_code_block`). Fluid escapes snippets and filenames. The controller loads only the eleven supported language choices, renders a nonselectable, screen-reader-hidden gutter and copies the original code text. The optional Clipboard API fallback restores keyboard focus and reports failure through the live status. No-JavaScript output retains the code and header; the unavailable copy button stays hidden.

### Responsive image slots

`Media/Image` accepts an optional `sizes` string; `Media/Media` forwards it for images, together with `eager`. Lazy images emit `sizes="auto, <sizes>"`, letting supporting browsers select candidates using the actual rendered slot, including Card padding, Card Grid gaps/columns, Carousel card widths, expanding Gallery rows, Image Only one–six columns and Textmedia orientations/nested hosts. This is native HTML behavior and needs no frontend controller. Eager images emit the explicit sizes string without `auto`; the existing eager/high-priority policy is unchanged. Omitted/empty sizes falls back to `100vw`.

The six affected block templates accept an `imageSizes` rendering variable and pass it through their media/Card slots. `ax:imageSizes(profile: 'image-only', columns: 'three')` and the other finite profiles supply conservative fallback bounds for the shipped 72rem host. Image Only divides the host by its fixed column count after subtracting 16px gaps. Card/Carousel bounds subtract the smallest shipped padding; Card Grid bounds allow an auto-fit single occupied track below its configured container breakpoint. Textmedia is capped at 36rem. Gallery retains a full-host fallback because incomplete and filtered rows may expand to one tile. Native `auto` uses actual dimensions for every variant, theme, gap and nested host.

Browsers without auto-sizes may transfer larger candidates for dynamic grids/nesting; the bounds deliberately avoid substituting viewport breakpoints for container queries. Custom hosts wider than 72rem, changed CSS/tokens, or eager custom compositions must supply their own sizes estimate. With JavaScript disabled, native lazy loading is disabled too; a browser may fetch the conservative fallback before layout and then fetch a second candidate for `auto`. Byte savings are therefore not guaranteed in that path. The existing 480px minimum and 1200px maximum (1600px Gallery) candidates remain unchanged. Caller strings describe fallback lengths/media conditions and must not include `auto` (the lazy partial adds it). The native Card's media slot remains caller-owned: pass sizes to the Image partial inside that slot; the scalar Card bridge has no image argument. FAL crops, original src/srcset candidate widths, dimensions, alternatives and caption escaping remain intact. Gallery original-file/lightbox links are unchanged.

Image Only (`astryx/image-only`, CType `astryx_image_only`) reuses the core `image` FAL field (up to 100 images), heading fields and spacing. `columns` accepts three (default), one, two, four, five or six; `aspect_ratio` accepts auto (Original, default), landscape (4:3), wide (16:9) or square (1:1). Unknown columns fall back to three through the finite `ImageOnly` StyleX recipe; unknown aspect values retain original proportions. The grid keeps the chosen count at every width and uses equal-width tracks with a 16px token gap; incomplete rows never expand. Shared `Media/Image` rendering preserves FAL cropping, dimensions, responsive sources, alternatives and escaped captions. Fixed frames use object-fit cover; Original adds no display crop. The backend preview mirrors columns and proportions without frontend JavaScript.

## Subpages navigation

`menu_subpages` uses the native `astryx:sideNav` component: one vertical list, 100% container width, no icons or sections. Figtree 14px/20px labels use normal weight and medium weight on the current/active branch. Rows use 8px horizontal padding, 32px minimum height, 10px radius and 2px gaps; long titles wrap. Neutral reference backgrounds are hover `light-dark(#0000000D, #ffffff0D)`, pressed `light-dark(#0000001A, #ffffff1A)` and selected `light-dark(#0000000F, #ffffff1A)`. Selected rows retain their fill on hover/press. TYPO3 menu processing, link targets and escaped titles are preserved; `aria-current="page"` marks only the current page. Links work without JavaScript and keep the shared keyboard focus ring.

`menu_pages` (Astryx Menu of Selected Pages) retains TYPO3's core `pages` field: an ordered page relation picker with the page browser and up to 50 selections. Its core MenuProcessor uses `special = list` and one level, preserves selection order and applies TYPO3 page visibility, language, workspace and access handling. No selection skips menu processing and produces no links. It renders through the same `Subpages.html` template and `astryx:sideNav` component as `menu_subpages`, including heading and spacing; it introduces no separate styles or JavaScript. Existing FSC `menu_pages` records retain their CType and stored page relations during migration.

## Sitemap tree navigation

`menu_sitemap` renders `astryx:treeList` from the core MenuProcessor, with all branches available up to the existing seven-level limit. TYPO3 controls page visibility, access, localization and workspace overlays. Unique component IDs and index-based branch paths identify labels and child groups, including repeated page references. No database fields or migration mappings change.

TreeList uses the shared theme typography, 8px row padding, 2px row gaps, a 16px logical indentation step and continuous vertical guide lines below parent chevrons. Leaves reserve the same chevron column whenever the tree contains a branch; flat lists have no reserved column. Labels wrap inside the content column. The `TreeList` recipe has finite `part` keys `list`, `group`, `row`, `link` and `toggle`; shared sources stay central because the native component is independently reusable.

Without JavaScript, semantic nested lists expose every page link and unavailable buttons stay hidden. Enhancement adds `tree`, `treeitem` and `group` roles, translated disclosure labels, synchronized `aria-expanded` and `aria-controls`, and one roving tab stop. Active/current branches open initially; other branches start collapsed. Up/Down visits visible rows; Right expands or enters children; Left collapses or moves to the parent (reversed in RTL); Home/End visits the first/last visible row; typing searches visible labels; `*` expands sibling branches. Enter follows the original TYPO3 link and target; Space toggles a branch. Tab exits the tree. Collapse preserves descendant expansion choices and restores focus to the parent when necessary. Reduced motion removes chevron transitions. The original links, escaped titles and `aria-current="page"` remain intact.

## Button and Hero contrast

Neutral/Ocean destructive Buttons use explicit paired background/foreground tokens: `#76000c`/`#ffffff` in light mode and `#ffc4be`/`#15110c` in dark mode. Stone retains its categorical red fill/text. Enabled normal, hover and focus states use the same pair at every size; disabled opacity is a separate inactive-control treatment. Complete theme tokens are reapplied at nested theme/mode boundaries.

Hero Overlay places the heading, subheader, eyebrow, rich text and inline links on a 54% transparent white panel with black foregrounds in every theme/mode. Secondary CTAs and the eyebrow use transparent fills and black text; primary CTAs retain their theme pair. Inline code has a transparent background within this panel. The FAL image alone fills the background; its escaped `figcaption` remains in normal flow below the content on its own matching 54% transparent panel with black text, so long captions grow the element. Overlay eyebrows wrap within the panel, and CTA height grows with enlarged text to keep glyphs on the control fill. Shared Button label truncation outside this contrast contract remains tracked separately. Padding protects black focus outlines from the outer clipping edge. Both Neutral/Accent variants and all aspect presets share this behavior without JavaScript. Black text over 46% white remains at least 4.5:1 even over black image pixels. This is the most transparent whole-percent opacity meeting that threshold for the chosen pair; theme-primary controls remain independently paired. Consuming-site overrides must preserve this contrast contract.
